# Loss Longer 跳绳计数

`loss_longer` 是 BeatDance 的正式计数算法。采集先写入原始 CSV，再逐包更新累计计数。实验、视频复核和停止后分析使用同一计数核心。输入为设备时间（秒）、三轴加速度（g）、三轴角速度（°/s）和启动片段号。超过 200 ms 的采样缺口会分段。

| 模块 | 工作方式 |
| --- | --- |
| 周期跟踪 | 加速度合模与三个角速度轴重采样至 50 Hz。每 80 ms 在约 1.84 秒历史内比较 0.28–0.82 秒滞后。波动达到 0.38 g、相关性达到 0.43 时，用加速度合模的基频相位定位周期事件。 |
| 落地候选 | 对加速度合模做 5 Hz 因果低通。取峰前升幅、原始合模最大正斜率、角速度合模峰峰值。固定逻辑回归评分和峰后回落确定候选强弱。候选通常在峰后 120 ms 窗口内判定。 |
| 起跳确认 | 暂存周期事件与落地候选，优先寻找间隔相容的三事件序列。间隔容差为 30%。超时、静默或结束时可按规则结算高可信的两事件序列。 |
| 失锁复核 | 波形失效或约 1.5 个参考周期未检测到新事件时进入复核。有证据的拍可补发。观察时间以 3.1 个周期、最多 2 秒为基准，再加候选确认窗口。 |

复核参考周期优先取最近最多三个有效周期事件间隔的中位数。起跳和失锁时可能在同一数据包发布多笔计数。连续跳通常由周期通道直接发布。

## 开发入口

- `beatdance/counting.py` 提供 `new_counter(params=None)`、固定模型与 `detect(records, params=None)`。
- `push(time, ax, ay, az, gx, gy, gz, segment=...)` 返回本包发布的事件。采集明确结束时调用 `finish()` 一次，结算尚未发布的最后一批。
- `beatdance/loss_longer.py` 管理正式默认参数、起跳和失锁逻辑。`waveform.py` 负责周期及相位，`landing.py` 负责候选特征。
- 回放中的 `time` 是估计时刻，`emitted_s` 是发布的设备时刻。另有 `source`、`count`、`period_s`。候选日志的 `decision_sample_time` 记录落地候选判定时间。
- 在 [计数实验台](COUNTING_LAB.md) 比较同一数据快照上的参数。历史实验保留原 ID、配置和结果供复核。新实验只运行 Loss Longer。

## 验证边界

迁移所用开发回放的累计发布数为 2539e79c **150**、fca92f01 **104**、xcy-2 视频覆盖范围内 **169**。三段在人工有效区间按 ±0.20 秒作一对一配对，总计 405 个匹配、16 个误计、19 个漏计。成功配对的落地到发布延迟中位数约 100 ms，P95 约 567 ms。它们是调参用录像，独立录像准确率及实物端到端延迟需另行验证。
