# 运行与验证

## 录视频时对时

已录制的数据可在工作台“视频复核”页输入视频时刻／屏幕采集时间，自动换算时间轴，并排播放视频和波形、慢放和记录疑似计数问题。具体步骤见 [视频复核](INFRA.md#视频复核)。

工作台的“采集”页显示大字采集时间。先开始采集并确认收到数据，再用视频拍清批次、片段号和秒数，连续拍摄动作，结束前再拍一次屏幕。显示值取自最近已保存样本的 `time`，不是点击开始后的电脑秒表；无样本显示等待，断流或停止后不继续走时，设备重启后的新片段重新从零计时。

若视频第 V 秒拍到采集时间 D 秒，初步换算为 `数据时间 = 视频时间 + (D - V)`，每个启动片段分别对齐。页面约每 0.5 秒刷新，加上网络和渲染延迟，小数三位不表示毫秒同步精度。为检查逐次漏计／多计，请额外录下佩戴传感器的手明显晃动等共同事件，再用视频与波形校准；同步动作排除在正式计数区间外。

## 正式采集与算法工作台

在软件仓库根目录运行 `.\.venv\Scripts\python -m streamlit run infra_app.py`。
七页分别为“采集／数据／标注／实验／对比／视频复核／算法实验台”。通过数据与标注页面准备固定数据集，再在算法实验台比较五种预置、扫描参数并查看误检／漏检；首次使用可在“数据”创建合成示例。标注、数据集及实验结果保存在本地独立目录，默认不入 Git，需另行备份。完整流程与命令行见 [INFRA.md](INFRA.md)。

离线计数操作见 [COUNTING_LAB.md](COUNTING_LAB.md)。视频复核选择“算法实验对比”，或在算法实验台使用默认“视频同步对比”，即可将保存的实验结果与本地视频同步播放。实验台不需要连接设备。

```powershell
# 已有数据集上运行五种预置；不采集、不调用付费服务
.\.venv\Scripts\python -m infra.counting_lab --root . --dataset DATASET_ID --question "比较计数规则"

# 视频同步逻辑回归
node --test tests/video_review_browser.test.cjs
```

以下命令均在软件仓库根目录运行。早期环境记录为 Python 3.14.7；实际依赖以当前环境和实验来源记录为准，`requirements.txt` 只写下限、不设上限。2026-11-05 本次代码检查通过 49 项 Python 回归与 7 项浏览器逻辑测试；这些不是实物精度证据，后续以实际测试输出为准。

## 安装和启动

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m streamlit run infra_app.py
```

已安装依赖时，只需执行最后一条。打开终端显示的本地网址。

依赖始终跟随最新稳定版，需要更新时执行：

```powershell
.\.venv\Scripts\python -m pip install --upgrade -r requirements.txt
```

升级依赖后建议先跑一遍回归验证。上游发布破坏性大版本（例如 pandas 主版本变更）时，如出现异常再按需回退，不要直接修改本地已装版本了事。

唯一正式入口为 `infra_app.py`，旧 `app.py` 已移除。默认进入“采集”页；已有记录在“数据”页浏览，旧分析 CSV 也可在该页专用区域查看。

## UDP 实时采集

1. 电脑与 ESP32 连接可互通的同一 Wi-Fi，ESP32 使用 2.4 GHz。
2. 硬件固件 `BeatDance_IMU_UDP.ino` 的 `PC_IP` 设为本机当前局域网 IPv4，`PC_PORT` 默认 `5005`。软件监听地址 `0.0.0.0` 不能作为硬件的目的地址。
3. 进入“采集”页，默认监听 `0.0.0.0:5005`，填写匿名参与者、动作类型、佩戴位置与方向、实验条件与备注。
4. 点“开始采集”。软件将有效且顺序正确的样本逐行写入 CSV 并 flush，再每 0.5 秒从 CSV 读取数据更新曲线。
5. 点“停止并保存”，释放端口，并生成整次采集的合加速度分析。进入“数据”可按批次浏览和导出；在“视频复核”选择采集并设置合加速度或单轴分析参数。

数据保存在 `data/recordings/UTC日期/唯一批次/`，每次开始使用新目录。原始六轴数据和派生分析分别保存。详见 [数据格式](DATA_FORMAT.md)。

遇到“等待 UDP 数据”，检查硬件 `PC_IP`、端口、Wi-Fi 客户端隔离和 Windows 防火墙的 Python/UDP 入站权限。正式工作台的采集页与硬件仓库的诊断工具 `imu_udp_plot.py` 不能同时占用同一 UDP 端口；也不要启动多个工作台会话同时采集；端口被占用会显示错误。排查端口占用：

```powershell
netstat -ano | findstr :5005
```

## 不用硬件复现接收问题

没有硬件时，可以把已保存的采集按原始时间节奏重新发成本机 UDP 报文，反复验证接收与显示：

```powershell
# 默认取最新一次采集，按 10 倍速发到 127.0.0.1:5005
.\.venv\Scripts\python -m scripts.replay_capture --speed 10

# 指定批次与端口；--loops 3 表示连续发三遍
.\.venv\Scripts\python -m scripts.replay_capture --source data/recordings/2026-11-04/121723_291114_4da4bcc3 --port 5006 --loops 3
```

回放发送接收端支持的 UDP v1 报文；采集页的样本计数、采集时间和六轴波形随回放推进，停止后保存完整分析。仅在验证批次中点击“开始采集”，再运行回放脚本；不要向正式动作采集批次发送回放数据。

接收端同时兼容两代固件报文：扁平格式（`ax/ay/az/gx/gy/gz` + `t_us`）与旧版嵌套格式（`acc_g/gyro_dps` + `t_ms`）。`seq` 按 uint32 校验，设备连续运行超过约 11 分钟也不会因序号超出 uint16 而整包被丢弃。

切换工作台页面会停止采集并生成分析。关闭/刷新浏览器造成会话失联后，接收器约 60 秒释放端口；之前写入的 CSV 保留。失联停止或进程异常退出后，可在视频复核页读取原始记录进行分析。机器休眠、进程退出或浏览器长期暂停后台刷新都会影响持续采集。

## 计数与调参

采集页逐包累计 Loss Longer 计数，页面约每 0.5 秒刷新。停止后的 `analysis_magnitude.csv` 保留事件估计时间和发布时刻。可在 [算法实验台](COUNTING_LAB.md) 用已标注数据快照比较参数。

## 回归验证

```powershell
.\.venv\Scripts\python -m unittest discover -s tests -v
```

测试通过本机 UDP socket 发送合成数据，覆盖 JSON→CSV→显示、独立批次、异常报文、序号缺口/回绕、完整分析和界面启停。测试文件写入 `.tmp/` 下的临时目录，不进入正式采集目录。

这类验证不替代 ESP32 实物网络联调，也不验证真实跳绳识别精度。波峰数量是算法输出，不能直接当作真实动作标注。
