# 离线计数算法实验台

本页是算法实验工具。真实硬件、声音闭环和真实跳绳精度需要另外验证。

## 启动与首次实验

在 BeatDance-Software 根目录运行：

```powershell
.\.venv\Scripts\python -m streamlit run infra_app.py
```

1. 在“数据”导入已有采集；在“标注”建立人工动作与 valid/exclude 区间，保存数据集快照。已有数据集可直接选用。
2. 进入“算法实验台”，填写实验问题，选择数据集和候选算法。默认比较 A0、A1、A2、B0。
3. 保持公共预处理一致，点击“批量运行”。刷新查看进度；切页不取消。各配置逐个执行，失败保留记录且不阻止下一配置。停止在片段边界生效。
4. 在“同数据对比”选择完成的实验；比较误检、漏检、时间误差和每片段结果。无标注或无有效区间显示 not_evaluated，不代表零误差。
5. 前两个实验分别为 A/B，查看 B recovered / B missed / both missed。点击差异或错误定位，所有算法共享时间窗。误检单独列出，不对两个相邻误检强行建立对应。
6. 填写结论与限制，生成独立 HTML 报告；包含嵌入图片、指标、配置与配对差异，离线打开不依赖 Streamlit。图示最多前六个片段，全部指标仍保留。更详细产物从原“对比”页导出实验 ZIP。

没有真实标注时，可在“数据”创建合成流程示例操作以上流程。合成结果只证明软件流程能运行。

## 预置算法与参数

共同步骤：输入现有六轴记录，按当前启动段处理；加速度从 g 转为 m/s²；按缺口拆分，重采样、四阶 Butterworth 零相位低通。原始输入不改写。实验分析整个启动段后裁剪选区，选区外样本可能参与离线滤波。所有候选都是离线算法。

| ID | 计数方法 | 参数意义 |
| --- | --- | --- |
| offline-butterworth-peaks-v1 | 原有 find_peaks，保持兼容 | prominence 为峰显著度，min_peak_interval 为间隔 |
| adaptive-amplitude-v1 | 候选峰显著度超过近期稳健幅度乘系数；固定间隔 | window_seconds、amplitude_factor |
| adaptive-interval-v1 | 固定显著度；由近期合格候选间隔中位数估计不应期 | interval_ratio、min_interval、max_interval |
| adaptive-both-v1 | 同时启用上述两种自适应 | 两组参数共同生效 |
| hysteresis-v1 | 上穿高阈值进入动作候选，回落低阈值后确认期间最高点 | high_sigma、low_sigma 和固定 min_peak_interval |

自适应幅度采用滚动中位数及 1.4826×MAD，显著度下限 0.05 m/s²。自适应间隔启动时使用 min_interval；近期候选的合理间隔中位数乘 interval_ratio 后裁剪到上下界。每个连续段重置历史。多个次峰仍可能污染周期估计，不能预设它优于固定法。

B0 需要完整回落才确认，片段末尾未完成候选不计；保留峰时刻作为事件时刻。candidates.csv 中 decision_sample_time 只标记状态机回落样本，不能当成在线确认时间，因为预处理本身使用未来样本。

A1/A2/A3 依时间顺序接受候选；A0 沿用 scipy 对峰间距冲突的处理。因此新方案与 A0 的差异也可能来自候选保留次序，应通过候选日志复核。

调试输出：analysis.csv 带逐点阈值；inputs/<selection>/candidates.csv 记录候选点、接受状态、拒绝原因与间隔。动态幅度 threshold 表示峰显著度门槛，不是信号纵轴上的绝对高度。静态阈值不为静止信号制造计数。

## 参数扫描与数据用途

支持一维扫描，和选择的算法做笛卡尔组合；每批最多 64 项。某参数仅对部分算法生效，扫描时应仅选择相关算法，以免重复生成等效配置。

开发集可反复调参，holdout 禁止在页面进行参数扫描。用途只是批次声明，不会自动检查参与者重叠、历史使用或阻止单次调参；应自行按完整会话/被试建立独立快照。标签来自采集 session.labels，展开逐片段结果可查看。当前不自动生成多被试统计显著性结论。

配对对比要求数据集内容哈希、统一匹配容差、缺口分段规则、评分策略一致。评分仍使用现有有效区间与一对一匹配，离线事件误差不等于实时延迟。无人工动作的有效干扰区间可统计误检。

## 保存、复现与命令行

每个配置复用现有 ExperimentJob，独立保存到 results/experiments/<id>/，记录数据与标注快照、算法参数、代码来源、事件、评分与失败日志。耗时存入 manifest.timings，不混入确定性评分。批次问题、用途、状态和子实验 ID 存入 results/counting_batches/<id>/；参数清单见 configs.json。生成报告时结论与报告还会独立保存到 results/counting_reviews/<id>/，不会覆盖已有复盘。进程意外退出时批次状态可能仍为 running，应核查各子实验状态，不会自动恢复或重跑。

```powershell
.\.venv\Scripts\python -m infra.counting_lab --root . --dataset DATASET_ID --question "比较五个预置"
```

## 扩展算法

实现统一函数 `detect(records, config, algorithm_id, params) -> DetectionResult`：analysis 保留 time、span、raw_acceleration、filtered_acceleration、is_peak；candidates 可为空但保留列头。接口不接收人工标注。

新增候选时在 beatdance/counting.py 注册 PRESETS 名称，并增加对应检测分支及参数校验。无需修改实验评分器或页面。自定义预处理也应在算法内声明，算法 ID 必须与版本对应。若要新增完全不同的输入/输出数据类型，应另行扩展契约。


## 视频同步对比

算法实验台选择完成的实验与片段后，默认显示“视频同步对比”；也可切回静态波形。原“视频复核”页的“复核内容”中新增“算法实验对比”，两处使用同一播放器。

1. 选择本地视频，填写视频秒 V1 与设备片段相对秒 D1，应用对齐；有漂移时使用第二同步点。时间始终是原采集时间，不会把裁剪片段开头重置为零。
2. 播放、慢放、拖动视频或点击波形时，各算法轨道共用游标与时间窗口。每条轨道显示其保存的原始/滤波信号、检测点、人工动作和漏检；有效/排除区间以背景表示。各轨道纵轴独立，横轴一致。
3. 在播放器内选择“波峰跳转使用”的算法，再使用前后波峰按钮；从“定位误检／漏检／差异”选择事件会暂停并跳到对应视频时刻。不在视频覆盖范围的事件会提示，不强行跳到视频端点。
4. 复核与对齐 JSON 绑定输入哈希、设备启动段、数据集内容、选区、实验顺序和配置。恢复时需选择相同实验与片段。原单算法复核记录仍可在原采集复核模式使用。
5. 下载“视频与算法对比页”可脱离 Streamlit 打开，重新选择本地视频并恢复导出的 JSON 即可继续。HTML 内嵌所选实验的采集波形和标注，不包含视频。实验结果使用保存产物，不会重新执行算法，也无需重新读取原始采集。

播放器内部播放、切换跳转算法、定位差异不会重载；改变 Streamlit 上方实验、片段、时间窗或其他控件可能重载，请先导出对齐与复核 JSON。更换本地视频会清除旧对齐与临时标记。人工标记仍是复核记录，不自动成为评分真值。同步精度取决于人工对齐与实际视频，逻辑测试不代表真实视频对齐精度已经验证。

浏览器联动逻辑检查：`node --test tests/video_review_browser.test.cjs`。
